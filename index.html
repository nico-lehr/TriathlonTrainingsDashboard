⠿

Fitness & Form (Performance Management Chart)
CTL (Chronic Training Load, 42-Tage-Ø) zeigt die aufgebaute Grundlagenfitness · ATL (Acute Training Load, 7-Tage-Ø) die kurzfristige Ermüdung · TSB = CTL − ATL, die „Form": positiv = frisch/erholt, stark negativ = hohes Übertrainingsrisiko. CTL/ATL werden immer aus der vollständigen geladenen Historie berechnet (nicht nur dem gewählten Zeitraum), damit die Werte stabil bleiben.

⠿

Trainingsbelastungsverhältnis (ACWR)

⠿

Trainingsmonotonie
Nach Foster (1998): Ø Tagesbelastung ÷ Standardabweichung der Tagesbelastung über ein rollierendes 7-Tage-Fenster. Hohe Werte (> 2,0) bedeuten sehr gleichmäßige Belastung ohne echte Erholungstage — das erhöht unabhängig von der absoluten Belastungshöhe das Übertrainingsrisiko.

⠿

Erholung & Gesundheit
Gemessene Werte aus Garmin Connect. Entscheidend ist nicht der Einzelwert, sondern die Abweichung von deinem eigenen Mittel: eine deutlich niedrigere HRV oder ein erhöhter Ruhepuls deuten auf unvollständige Erholung hin. Tage ohne getragene Uhr bleiben Lücken und werden nicht als Null gewertet.

Zuletzt gemessene Werte im Vergleich zum eigenen Mittel

Ernährung
Rein rechnerisch, keine KI-Schätzung — die Werte kombinieren dein Körpergewicht, deinen Trainingsplan (heutige/nächste geplante Einheit) und dein Hauptevent-Ziel mit etablierten Sporternährungs-Richtlinien (ACSM/ISSN). Ohne Körpergewicht im Profil bzw. ohne Zielzeit bleiben die jeweiligen Karten leer, statt etwas zu erfinden.

Makro-Ziele, Pre-Workout-Timing und ein Wettkampf-Verpflegungsplan — abgestimmt auf deinen Trainingsplan.

Gewichtsverlauf

Wird für die Berechnungen unten genutzt (Makros pro kg Körpergewicht) und als Verlauf gespeichert.

Tagesziel Makros
Kohlenhydrate richten sich nach dem heutigen geplanten Trainingsumfang (bzw. Carb-Loading kurz vor dem Hauptevent), Eiweiß und Fett sind feste Richtwerte für Ausdauerathleten. Quellen: ACSM/AND/DC-Positionspapier (2016), ISSN-Positionspapier Protein (2017).

Vor dem Training
Bezieht sich standardmäßig auf deine nächste geplante Einheit im Trainingsplan, per Klick auch auf eine der Einheiten danach. Da geplante Einheiten keine Uhrzeit haben, ist die Angabe relativ zum Start ("X Stunden vorher"), nicht als feste Uhrzeit.

Zeigt immer die tatsächlich im Kalender geplanten Einheiten — bei mehreren anstehenden Einheiten oben umschaltbar.

Wettkampf-Verpflegung
Aus den Zielzeiten deines Hauptevent-Ziels (★ bei „Deine Ziele" im Coach-Tab). Erscheint erst ausführlich ab der Taper-Phase (14 Tage vor dem Wettkampf) — vorher bleibt die Kachel bewusst klein, da sich Zielzeiten und Verpflegungsbedarf bis dahin noch ändern können. Ohne hinterlegte Zielzeit je Teildisziplin kann ohnehin keine Dauer und damit kein Verpflegungsbedarf berechnet werden.

Einstellungen

Gelten für das ganze Dashboard, nicht nur den Coach-Tab. Profil und Trainingsdaten liegen auf dem Dashboard-Server (nur für dich sichtbar), die Verbindungs-Einstellungen nur auf diesem Gerät.

Konto

Angemeldet als …. Beim Abmelden wird alles Persönliche aus diesem Browser entfernt.

Ollama-Verbindung

Für den KI-Coach (Trainingsempfehlungen, Auswertungen). Ollama läuft auf dem Dashboard-PC, die Anfragen gehen über den Dashboard-Server – deine Daten verlassen das eigene Netz nicht.

Einmalig auf dem Dashboard-PC einrichten: Ollama installieren und ein Modell laden (Terminal: ollama pull llama3.1). Läuft Ollama auf einem anderen Rechner, die Adresse in der Datei .env eintragen (OLLAMA_URL) — Details in docs/DEPLOYMENT.md.

Claude API (optional)

Alternative bzw. Ergänzung zu Ollama — nutzt ein stärkeres Modell über die Anthropic API (kostenpflichtig, eigener API-Key). Läuft direkt aus dem Browser, kein eigenes Backend nötig.

API-Key erstellen unter console.anthropic.com. Standardmodell ist bewusst das gündigste verfügbare (Haiku), um die Kosten so gering wie möglich zu halten. Der Key wird nur lokal in diesem Browser gespeichert, nie an einen eigenen Server geschickt.

Hybrid-Modus — welche Aufgabe nutzt welchen Anbieter?

Standardmäßig läuft alles lokal & kostenlos über Ollama. Einzelne Aufgaben können gezielt auf Claude umgestellt werden, z.B. nur die selten aufgerufene Trainingsplan-Erstellung — so bleiben die API-Kosten minimal.

Persönliche Daten

Optional. Name wird z.B. in Begrüßungen genutzt, Geburtsdatum nur für eine Geburtstags-Nachricht im Dashboard - beides wird nirgends sonst ausgewertet und ersetzt nicht das Coach-Onboarding (Leistungswerte/Ziel) unten.

Trainingswerte

Optional — hilft dem Coach bei konkreteren Empfehlungen und schaltet einzelne Kacheln frei.

Maximale & Ruhe-Herzfrequenz werden für TRIMP und die Herzfrequenzreserve in der Trainings-Detailansicht gebraucht (Trainingsbelastung-Kachel) — ohne diese zwei Werte bleibt sie ausgeblendet. Das Körpergewicht wird nur für die Rad-VO2max-Schätzung aus Leistungsdaten (Watt) gebraucht — ohne Gewicht bleibt diese Schätzung leer, statt geraten zu werden.

Equipment
Kilometerstand von Laufschuhen/Rad wird automatisch aus deinen Trainings gezählt, solange ein Item als "Standard" für die Sportart markiert ist. Verschleißteile (Kette, Reifen, Bremsbeläge) teilen sich die Kilometer des zugehörigen Rads. Warnt hier, im Kalender und auf dem Dashboard, sobald ein Service-/Austausch-Intervall erreicht ist.

Optional — nur sichtbar, wenn du Equipment hinterlegst.
